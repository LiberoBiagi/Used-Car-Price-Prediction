## 📌 Overview

Cars 4 You is a fast-growing online car resale company. Today every car is appraised on site by a mechanic, which is slow and does not scale with demand. This project builds a regression workflow that **estimates the purchase price from the car's attributes**, so that the model can act as a pre-filter and only selected cars are sent to manual inspection.

**Main result:** a **Random Forest trained separately for each brand** reaches a validation **MAE of about 1,213** (RMSE 1,949, R² 0.958) on car prices, using the cleaned and engineered dataset described below. The model is meant as a price pre-estimation, not as a final purchase price.

## 🗂️ Data

Each row is a car with: `Brand`, `model`, `year`, `price` (target, train only), `transmission`, `mileage`, `fuelType`, `tax`, `mpg`, `engineSize`, `previousOwners`, `hasDamage`, indexed by `carID`. The column `paintQuality%` is dropped.

The raw data are noisy: inconsistent capitalisation and whitespace, truncated brand names (`v`, `toyot`), typos in model/transmission/fuel type, impossible values (negative owners/mileage, fractional years, implausible years such as 2023–2024 for a 2020 dataset) and many missing values. The notebook reads `data/train.csv` and `data/test.csv` from this repository's GitHub raw URL, so the files must be in `data/` on the `main` branch.

## 🔬 Methodology

```
Cleaning → Price outliers → Encoding → Stratified 80/20 split → Imputation
   → Feature engineering → Feature selection (filter, RFE)
   → Brand-specific models → Random-search tuning → Retrain on train+val → Predict test
```

**1. Cleaning (`preprocessing.py`)**
- Lowercasing and trimming, brand name mapping, **fuzzy matching** (`thefuzz`) of `model`, `transmission` and `fuelType` against reference lists
- Numeric rounding and absolute values, implausible years (2023, 2024) set to missing, `hasDamage` converted to `stated_no_damage`
- Price outliers replaced with missing values per model (IQR × 3), later imputed

**2. Split and imputation (`imputation.py`)**
- Categorical columns label-encoded; 80/20 train/validation split **stratified by brand × price tercile**
- Imputers are fitted on the training split only and applied to both: (1) **mode imputer** for missing brands from the model name, (2) **IterativeImputer with ExtraTrees** for the other features, (3) **ExtraTrees price imputer** for the removed outliers
- The test set is cleaned with imputers refitted on all available training data

**3. Feature engineering (`Engineering.py`)**
`age` (2020 − year), `mileage_per_year`, `efficiency_ratio` (mpg / engine size), `age_mileage`, `age_squared`, `is_premium_brand` (BMW, Mercedes, Audi), model-level price statistics (mean, std, median) computed on the training set, and **smoothed mean encoding** of `model` and `Brand`.

**4. Feature selection (`Selection.py`)**
- *Filter* (variance threshold, Spearman |ρ| > 0.85, ANOVA F-test): performance dropped, so it was not used
- *Wrapper* (**RFE with Random Forest** on numeric features): 14 of 17 numeric features kept (`previousOwners`, `stated_no_damage` and `is_premium_brand` discarded) with no loss of performance and faster training

**5. Models (`Train.py`)**
`BrandModelTrainer` fits one pipeline (`RobustScaler` + `OneHotEncoder` + estimator) for each of the 9 brands: Audi, BMW, Ford, Hyundai, Mercedes, Opel, Skoda, Toyota, VW.

**6. Tuning (`Tuning.py`)**
`HoldoutRandomSearch` with **120 random configurations** over `n_estimators`, `max_depth`, `min_samples_split`, `min_samples_leaf`, `max_features`, `min_impurity_decrease`, `max_samples` and `criterion`, optimising MAE on the validation set. It keeps both the best overall configuration and the best configuration per brand.

## ⚠️ Limitations

- Model-level price features (mean, median, std) are computed from training prices, so **training metrics are optimistic**; the validation scores are the reference.
- The model scores a brand never seen in training as 0, so new brands require retraining.
- Premium brands remain hard to predict (higher MAE) because many cars have similar specifications but very different prices.
- Customers enter the data themselves, so it can be biased. We recommend using predictions as a filter before manual inspection, not as the final price.

**Future work:** modern tabular models (advanced gradient boosting, attention-based architectures), brand-specific neural networks, brand-specific feature subsets guided by SHAP, and additional data from external sources.
